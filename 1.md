# 0. ORDEN PRINCIPAL

Construir **Atlas GT**, una plataforma industrial robusta, modular, extensible, offline-first y edge-first cuya función sea conectar, descubrir, observar, traducir, normalizar, historizar y exponer información procedente de la mayor variedad razonable de máquinas, PLC, sensores, controladores, buses, dispositivos legacy y equipos modernos.

Atlas GT debe comportarse como una **navaja suiza de conectividad industrial**.

No diseñar Atlas GT alrededor de una marca, protocolo, PLC o máquina.

El núcleo debe sobrevivir a la incorporación futura de tecnologías que hoy no conocemos.

El primer producto funcional construido sobre el núcleo será:

Pero Count **NO define la arquitectura**. Es solamente el primer consumidor del Core.

# 2. PRINCIPIO DE SEGURIDAD

Una máquina desconocida jamás recibe comandos automáticamente.

Estado inicial obligatorio:

`PASSIVE`

Escalera de confianza:

`Unknown`
→ `Observed`
→ `Decoded`
→ `Verified`
→ `ReadOnly`
→ `WriteCapable`
→ `ControlCapable`

AtlasGT puede promover automáticamente información hasta **Observed**.

Puede producir hipótesis para **Decoded**.

La semántica inferida debe conservar:

* evidencia;
* muestras;
* origen;
* algoritmo;
* confianza;
* fecha;
* dispositivo;
* interfaz;
* sesión.

Una inferencia no se convierte silenciosamente en verdad.

WRITE y CONTROL requieren autorización explícita y políticas específicas.

En sistemas OT reales, priorizar observación pasiva.
